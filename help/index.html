D30 Widgets: common problems

The widget isn't in the home screen's widget picker

Open Project Settings > D30 > Widgets. The widget has to be ticked under Widgets Included in Build, and there has to be a slot of the same size that uses it as its default.

On Android, also check that the Android package is installed. On iOS, the exported Xcode project should have a D30Widgets target. If you build with Append, try a clean export.

iOS: the widget shows up, but changes from the game never reach it

The game and the widget share data through an App Group. Automatic signing sets it up for you. With manual signing you need to create the App Group yourself, plus a provisioning profile for <bundle id>.d30widgets that includes it.

Device clouds and other services that re-sign the app drop the App Group, so test this on your own device, TestFlight or an Ad Hoc build.

A call returns UnknownKey, UnknownSlot or UnknownWidget

The name doesn't match anything in Project Settings. Names are case-sensitive, so energy/count and Energy/Count are different keys.

A call returns WrongProperty

The key belongs to a different kind of element. Calling SetText on an image key does this.

The countdown doesn't tick

It ticks on iOS 16+ and Android 7.0+. On Android 6 the widget shows the end time instead. On iOS 15 it only updates when the time runs out.

Scheduled updates arrive late on Android

Android delays alarms to save battery, and on Android 12+ the delay can be a few minutes. If the player force-stops the game, nothing arrives until they open it again. iOS doesn't have this problem.

iOS: the animation only shows its first frame

That's the default on iOS. Looping animation is an experimental option for iOS 18+ and comes with limits on length and frame rate. The package docs have the details.

The Widget Editor shows a D30W… code

The editor's Console panel explains it and says what to change. All codes are listed in Documentation~/diagnostics.md inside the package.

Reporting a bug

Whatever you can include from this list helps:

  • Plugin version and Unity version
  • Platform, OS version and the device
  • What happened, and what you expected instead
  • The Unity Console output, including any D30W… codes
  • For build errors, the build log (and on iOS, whether signing is automatic or manual)
  • The widget asset or a small project where it happens
